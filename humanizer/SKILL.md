# Humanizer 去 AI 味写作

Source: github.com/blader/humanizer（MIT）。让 AI 写出的文字听起来像人写的，而不改变原意。依据是维基百科编辑用来识别 AI 生成文本的指南《Signs of AI writing》，内含 26 条可查的“AI 味”模式。2026-11-09 一周 GitHub 趋势榜在列，仓库星数超 6.6 万。

## 这是什么

- 一套改写方法论，不是检测器绕过工具：目标是让文字读起来像写给真人读者，而不是骗过 AI 检测器——作者明确说明，检测器多数情况下仍会把改写后的文本标出来。
- 核心洞察：语言模型默认写“对最广读者、最广主题都最可能成立”的句子；人是为一个读者、一个主题做选择。26 条模式都是这种“默认选择”的不同表现：用套话代替事实、用规则套节奏和格式、把普通事实吹成关键转折、留下聊天残留、给已经懂的读者再解释一遍。
- 工作方式：先按强度顺序标出文本里所有命中模式，再不拘泥原结构起草改写稿，用模式表和原文事实逐条核对，最后成稿；全程不编造——人名、数字、日期、引文必须来自原文或作者本人，缺了就问，不编。

## 什么时候用

- 给视频写简介、标题、置顶评论、公众号/小红书文案时用：AI 味重的简介一眼就能看出来，直接影响点击和信任。
- 给 aivorka 站点、作品页、更新日志写文案时用，尤其适合“不要 AI 味、要像人写的”这类要求。
- 改写任何一段 AI 起草的中文或英文 prose 时用：技术说明、产品介绍、个人随笔都适用；技术与参考类文字保持中性简洁，个人文字保留作者的观点和怪癖。
- 不适合改写代码、数据、法律条款这类必须逐字准确的文本；也不适合用来伪装成他人写作或应付原创性审查。

## 安装

- Claude Code：`/plugin marketplace add blader/humanizer`，再 `/plugin install humanizer@humanizer`（调用为 `/humanizer:humanizer`，需 Claude Code 2.1.142+；旧版改用 `npx skills add blader/humanizer --global --agent claude-code`）。
- Codex：`npx skills add blader/humanizer --global --agent codex`。
- 其他 Agent：`npx skills add blader/humanizer --global --agent '*'`；去掉 `--global` 只装当前项目。
- Muse：本技能只存用法说明，不替用户安装；是否安装、装到哪个 Agent，由用户决定。没装也能按下面的模式表手工改写。

## 核心用法

- 调用方式：在 Agent 里说“humanize 这段文字”或 `/humanizer` 后贴文本；改写文件时给路径，如“把 docs/launch-post.md 里的人味改出来”，只改 prose，代码、数据、frontmatter、链接目标不动。
- 匹配作者声音：想让改写像用户本人写的，先贴 2–3 段用户自己的文字做样本；改写会跟随样本的节奏、用词、标点和有意保留的怪癖（包括破折号用法）。
- 改写流程：第一稿→自我批评（还有哪里听着像 AI）→终稿；贴文本时展示这个过程，改文件时直接落改动。
- 26 条模式（按强度和出现频率编号；前 5 条单次出现就值得改；标 *weak alone* 的单独出现不算，几条凑在一起才算）：
  - A. 铺垫代替陈述：1. “不是 X 而是 Y”；2. 每段结尾一句煽情收束（“这才是真正的胜利”）；3. 听着深刻的套话（“归根结底，真正重要的是……”）；4. 开场白式铺垫（“说真的？”“让我们深入看看”）；5. 和不存在的反对者辩论（“我不是说 X，但是……”）。
  - B. 按规则套节奏：6. 强行三联排比；7. 连续同句式开头；8. 破折号当万能连接符*；9. 堆叠限定词（“可能或许大概可以说”）*；10. 到处用连字符复合词*；11. 被动语态、缺主语*。
  - C. 夸大与借来的权威：12. AI 高频词（delve、testament、landscape、showcasing 之类）；13. 夸大意义（“标志着关键时刻”“未来一片光明”）；14. 含糊的关联（“与……的领导有关”）；15. 空洞的 -ing 伴随状语（symbolizing、reflecting……）；16. 推销腔（“坐落在美不胜收的……”）；17. 借来的权威（“专家认为……”“被纽约时报、BBC 引用”）；18. 避开 is/are/has，用 serves as、features、boasts 之类。
  - D. 按规则套格式：19. 加粗当装饰；20. 装饰性标题（首字母大写堆砌、🚀、箭头）；21. 花引号*。
  - E. 聊天与草稿残留：22. 聊天机器人客套（“好问题！”“希望对你有帮助！”）；23. 知识边界免责与猜测（“现有资料有限，看起来……”）；24. 标题在首句里重复一遍；25. 写文档本身而不是写主题（“下表对比了……”）。
  - F. 写给错的读者：26. 给已经懂的读者再解释一遍——先给结论，诊断和证明留给后面的工单。
- 中文写作的对应处理：26 条模式按英文写成，但原理通用。中文里对应的 AI 味是“不仅……更是……”“值得一提的是”“总而言之”“让我们一起……”“这不仅仅是……更是一种……”这类固定搭配、三联排比和每段结尾的升华句；改写时按同一原则处理：删铺垫、删升华、留事实。

## 注意事项

- 不编造事实：改写不改变原意，不添原文没有的细节；缺一个关键事实时停下来问，而不是补一个看着合理的。
- 前 5 条模式最优先：一段文字里先改“不是 X 而是 Y”、煽情收束、深刻套话、开场铺垫和无对象辩论，改完这 5 条，AI 味已经去掉大半。
- 弱模式别单挑：标 *weak alone* 的模式（如破折号、连字符、被动语态）单独出现可能是作者有意为之，只有几条凑在一起才动手。
- 不要为了去 AI 味而把文字改得更差：删掉的是套话和水分，不是信息；删完读一遍，确认每个事实、数字和主张都还在。
- 与 hallmark / impeccable 分工：那两个管页面长什么样，这个管文字读起来像不像人写的；写落地页文案时两个可以一起用。
